## Items

### 1. Turbo cache correctness & efficiency — `turbo.json`

- **`pack:smoke` must hash the shared script it runs.** Each leaf package's
  `pack:smoke` calls `node ../utils/pack-smoke.mjs`, but that file is outside
  the package, so Turbo's default input hash ignores it — editing the smoke
  logic can silently reuse a stale pass. Add explicit `inputs`:
  ```jsonc
  "pack:smoke": {
    "dependsOn": ["build"],
    "outputs": [],
    "inputs": ["$TURBO_DEFAULT$", "$TURBO_ROOT$/packages/utils/pack-smoke.mjs"]
  }
  ```
- **Scope `build` inputs** so editing e2e/tests/demo/docs-of-a-package doesn't
  bust that package's library build cache (currently it does):
  ```jsonc
  "build": {
    "dependsOn": ["^build"],
    "outputs": ["dist/**", "build/**"],
    "env": ["DOCS_URL", "DOCS_BASE_URL"],
    "inputs": [
      "$TURBO_DEFAULT$",
      "!e2e/**", "!demo/**",
      "!**/__tests__/**", "!**/*.test.*", "!**/*.browser.test.*",
      "!**/__screenshots__/**",
      "!README.md", "!CHANGELOG.md"
    ]
  }
  ```
  (These exclusions are inert for `@rxova/docs`, which has no `demo/`/`e2e/` and
  whose content lives under `docs/` — not excluded.)
- **Quiet warm-run log replay** with `outputLogs: "new-only"` on the cacheable
  tasks (`build`, `typecheck`, `test`, `test:coverage`, `check:exports`,
  `pack:smoke`, `size`). Turbo 2.x takes this per-task; confirm during
  implementation whether a single top-level default is accepted and prefer that
  if so.
- **Skip** the audit's "package-specific outputs" suggestion — the generic
  `dist/**`/`build/**` outputs are correct (Turbo only captures what exists),
  and the one real problem it caused (`.docusaurus`) is already fixed. Note it
  as considered-and-declined to avoid config churn for marginal clarity.

### 2. Package-contract completeness

- **`engines.node`** — add `"engines": { "node": ">=20.19.0" }` to
  `packages/react-otp-input/package.json` and `packages/codemod/package.json`
  (currency/rating/meta already have it; matches the CI Node floor; clears the
  publint warning on OTP).
- **`@rxova/codemod` publish validation** — it ships a `bin` + `./transforms/*`
  exports with no validation. Add:
  - devDeps `publint` + `@arethetypeswrong/cli` (same versions as the leaf libs),
  - script `"check:exports": "publint --strict && attw --pack ."`.
    The existing Turbo `check:exports` task + the CI `package` job pick it up
    automatically. **Verify during implementation**: codemod is CJS-only with no
    `.` root export and a `bin`; `attw`/`publint` may need a targeted
    `--ignore-rules` (e.g. CJS-resolution rules) or `publint` config. Adjust to a
    clean pass; if `attw` is fundamentally unhappy with a bin-only CLI, keep
    `publint --strict` and drop `attw`. A bespoke tarball-CLI smoke test (audit
    suggested) is **optional/low-value** given the codemod already has a
    jscodeshift test suite — implement only if `check:exports` proves trivially
    extensible; otherwise defer with a note.
- **Meta size budget** — `@rxova/react-inputs` carries `size-limit` +
  `@size-limit/preset-small-lib` devDeps but no budget. Add:
  - new `packages/react-inputs/.size-limit.json` measuring the full-suite import
    from `dist/index.mjs` (`{ CurrencyInput, Rating, OtpInput }`) and optionally
    a single-component import to prove tree-shaking, each `ignore`-ing
    `react`/`react/jsx-runtime` (mirror the leaf-lib `.size-limit.json` shape),
  - script `"size": "size-limit"`.
    Set the limit from the measured baseline (~sum of the three, gzipped) with a
    little headroom. The Turbo `size` task + CI `package` job then cover it.

### 3. Docs / tooling nits

- **`pnpm docs` → `pnpm run docs`** in `README.md:45` (pnpm 11 has a built-in
  `docs` command that can shadow the script). Single occurrence; also sanity
  the neighbouring `docs:build` line.
- **TypeDoc broken anchors** — `apps/docs/docusaurus.config.ts` generates two
  broken `#property-*` anchors on interface API pages (the index links to
  `interfaces/X#property-y`, but `interfacePropertiesFormat: 'table'` emits no
  per-property heading anchors). Fix by adjusting the `typedoc-plugin-markdown`
  anchor/format option in `typedocDefaults` — most likely switching interface
  property rendering so anchors exist (e.g. `interfacePropertiesFormat: 'list'`)
  or enabling the plugin's HTML-anchor option. Rebuild, confirm **0 broken
  anchors**, and **leave `onBrokenAnchors` at the default `'warn'`** (do not add
  `'throw'`). This is an investigate-and-tune step.

### 4. CI `.turbo` cache reuse — `.github/workflows/ci.yml`

Dependency (pnpm store) caching exists via `setup-pnpm`; Turbo's local cache
(`.turbo`) is not reused across runs, so every runner recomputes. Add an
`actions/cache@v4` step for `.turbo` to the jobs that invoke Turbo — `static`,
`browser`, `e2e`, `package` — placed after checkout/`setup-pnpm`:

```yaml
- name: Cache Turbo
  uses: actions/cache@v4
  with:
    path: .turbo
    key: turbo-${{ github.job }}-${{ runner.os }}-${{ github.sha }}
    restore-keys: turbo-${{ github.job }}-${{ runner.os }}-
```

Per-job keys (jobs run different task subsets) with a `restore-keys` prefix for
cross-run reuse. Skip `unit` and `react-minimum` (they invoke vitest via
direct binary / `pnpm --filter`, not Turbo) and `changeset`. Optionally factor
the step into a tiny `.github/actions/turbo-cache` composite if the four
copies feel heavy — inline is fine.
